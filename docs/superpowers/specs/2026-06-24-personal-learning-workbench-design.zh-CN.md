# 个人 AI 学习工作台设计规格

## 范围

将现有 React 课程重构为一个**个人、本地优先的 AI 工程学习工作台**。这是产品 PRD 的 P0：本次不做登录、云同步、团队视图和实时 AI 教练，但会保留清晰的扩展边界。

本次不是在既有 Day01–Day13 后追加内容，而是按能力依赖关系重构为 Day01–Day20；README 与 Markdown 课程材料必须同步到最终可运行实现。

## 学习者与最终结果

目标学习者是已有前后端经验的工程师。每天约 60 分钟，并产生可复核的工程产出：判断、设计、实现草图、评估资产或项目证据。

完成后，学习者应能定义、构建、评估、运营并迭代一个面向生产的 AI 产品，而不是只会辨认模型术语或平台名称。

## 课程架构

课程以能力前置关系组织；平台和框架只作为相关能力日中的实现路径，不再作为课程主线。

| 阶段 | 天数 | 能力结果 |
| --- | --- | --- |
| 定义可靠 AI 行为 | 01–05 | 定义可测任务；划清模型边界；安全使用 Prompt、证据、工具、工作流与 Agent。 |
| 构建生产系统 | 06–11 | 设计 AI UX、知识生命周期、策略控制、评估、可观测性、成本/延迟与技术选型。 |
| 扩展与运营 | 12–16 | 处理多模态/实时输入、可恢复执行、发布治理与 AI SRE。 |
| 交付可验证项目证据 | 17–20 | 完成项目发现、架构/数据契约、实现与评估、发布/复盘及能力证据沉淀。 |

每一天都包含：明确目标、核心概念、**关系型**架构图、生产案例与反例、开放实践任务、至少 4 道加权题、复盘建议和权威参考。

## 应用边界

### 课程路线域

`curriculum` 负责阶段顺序、前置关系、标题、摘要与每日可验证目标。Day01–Day20 的路由列表和系列导航只能以它为唯一事实来源。

### 课程内容域

`lesson-content` 负责概念、案例、实践任务、参考资料和图示规范；它不得保存 React 状态或浏览器持久化逻辑。

图示按**关系类型**选择，而不是统一画成从左到右的流程：

- 模型、策略和业务系统之间使用责任/边界图；
- 摄取、版本和删除使用生命周期图；
- 组件及所有权使用分层系统图；
- 可恢复工作流和审批使用状态图；
- 评估、运营与产品学习使用反馈闭环图。

桌面端图示必须独占整行。窄屏时先缩小节点、标签与内边距，并转换为紧凑网格；绝不允许重叠。

### 评估域

`assessment` 负责题目权重、得分和复盘推导。每一日总分固定为 100 分；权重反映能力重要性，例如架构判断 30 分、核心概念 20 分、应用诊断 15 分、回忆检查 10–15 分，而不是按题数均分。

学习者以题号切换为主，上一题/下一题保留为辅助操作。题号只表达当前/非当前状态；当前题分值展示在题干的元信息区域，而不是题号项目中。复盘与历史记录统一以 100 分制显示。

### 学习者状态域

`learner-state` 通过适配器保持本地优先，保存当前答案、尝试历史、薄弱能力、实践证据和导出记录。后续可替换为云端适配器，不影响课程或评估组件。

### 工作台 UI 域

沿用已部署的视觉语言：暖白纸张底色、深蓝系统/选中状态、金色主行动、克制的棕红标签和高对比编辑式排版。

Hero 层级固定为一个小上下文标签、一个可读的能力陈述和一段紧凑结果说明。标题行高保持舒适（约 1.3–1.4）；除非断点确实需要，不人为强制换行。

## 响应式导航

应用包含五个内容锚点：路线、概念、架构、练习和复盘。

- **桌面端：** 视口右边缘始终保留一个折叠把手。hover 或键盘 focus 后展开右侧浮动菜单。它使用高层级 overlay，绝不改变正文网格宽度。active 状态来自直接章节路由和视口观察。
- **H5：** 不显示固定右轨；页面头部内提供紧凑、可横向滚动的文字导航，用 active 下划线而不是厚重按钮。它不能遮挡标题或图示控件。
- 导航支持点击、键盘焦点、直达章节 URL 与滚动同步，且程序化滚动时不会被错误覆盖。

## 个人学习工作台体验

每一天仍是一页式学习体验，但各区块形成清晰的证据闭环：

`能力路线 → 概念 → 架构判断 → 开放实践证据 → 加权测验 → 复盘 → 能力证据`

P0 只在本地保存实践证据；不伪造云端档案、团队面板或 AI 教练。

## 文档契约

- `README.md` 必须描述实际的 Day01–Day20 应用、启动/构建/测试命令、本地优先范围和发布行为。
- `docs/interactive-learning/overview.md` 是课程的唯一 Markdown 总览，与应用标题和顺序一致。
- 每份 `docs/interactive-learning/dayXX.md` 符合学习计划课程约定，并与应用课程数据对应。
- 产品和架构文档须清楚区分 P0 本地能力与后续 PRD 阶段。

## 验证

自动化验证覆盖：

1. Markdown 与类型化课程数据均为 20 天，路由和排序标题一致。
2. 每天都具备所需概念、架构/关系图、实践、至少 4 道题，以及总计 100 分的权重。
3. 每道题对应的概念属于当日课程；每条能力复盘建议都可定位到内容。
4. 直达导航、滚动同步、桌面折叠/展开导航语义和 H5 导航行为均保持可访问。
5. 加权得分下的复做、历史、导出和存储迁移正确。

人工响应式验收覆盖 375、768、1024 和 1440 px：固定导航不得改变正文宽度，图示不得重叠或溢出。

## 不在本次范围内

不引入认证、云端持久化、协作/团队视图、外部项目提交、实时 RAG/AI 教练、AI 自动评分或生产后端。
